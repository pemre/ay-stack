# 🌜 @ay/tokens

Core and semantic CSS custom properties for the Ay design language, with a
Tailwind v4 theme entry. No runtime, no dependencies — just CSS.

Token tiers, naming patterns, and tier ownership rules:
[TOKEN-ARCHITECTURE.md](./TOKEN-ARCHITECTURE.md).

## Install

```bash
pnpm add @ay/tokens
```

Inside this workspace the package is already wired through the `workspace:`
protocol, so no install step is needed.

## Consumption paths

### Plain CSS — no Tailwind

```css
@import "@ay/tokens";
```

Resolves to `dist/tokens.css`: the core tier as `:root`, the semantic tier, and
the `[data-theme="dark"]` overrides. It contains no Tailwind at-rule, so it works
in plain Vite, plain PostCSS, or a raw `<link>` tag.

### Tailwind v4

```css
@import "tailwindcss";
@import "@ay/tokens/theme.css";
```

Order matters: `tailwindcss` first, so the token block extends and overrides the
default theme rather than being overridden by it. `theme.css` declares the core
tier inside `@theme static`, which makes those values available both as custom
properties and as Tailwind utility namespaces — `bg-amber-500` renders the brand
amber, `text-gray-900` the brand near-black.

### Subpaths

| Specifier | Contains |
| --- | --- |
| `@ay/tokens` | core as `:root` + semantic + dark. No Tailwind at-rules. |
| `@ay/tokens/theme.css` | core as `@theme static` + semantic + dark. |
| `@ay/tokens/core.css` | core as `:root` only — layer your own semantic tier. |
| `@ay/tokens/semantic.css` | semantic + dark only — supply your own core scale. |

## Theme switching

Set `data-theme="dark"` on a root element. Every semantic token is re-declared in
the dark block, and `color-scheme` follows, so form controls and scrollbars match.

```html
<html data-theme="dark">
```

## Development

```bash
pnpm --filter @ay/tokens build      # derive dist/ from src/
pnpm --filter @ay/tokens test       # property and unit checks
pnpm --filter @ay/tokens typecheck
pnpm --filter @ay/tokens lint
```

`src/core.css` and `src/semantic.css` are the only files to edit. Everything in
`dist/` is generated by `scripts/build-css.mjs`, which rewrites
`@theme static { … }` to `:root { … }` and changes nothing else.
